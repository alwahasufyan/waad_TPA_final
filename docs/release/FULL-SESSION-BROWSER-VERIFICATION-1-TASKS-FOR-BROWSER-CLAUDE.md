# مهام اختبار متصفح شاملة — كل تغييرات الجلسة (قبل الدفع النهائي)

انسخ هذا الملف بالكامل وأعطه لجلسة Claude التي تملك أداة تحكم بالمتصفح. هذه مهمة **اختبار فقط** — لا تعديل كود، لا commit، لا push، لا merge.

## السياق

مشروع WAAD TPA، الفرع `medical-dictionary-remediation`. تم تنفيذ مجموعة كبيرة من الإصلاحات والمراجعات هذه الجلسة — بعضها مدفوع فعلاً لـ GitHub (commits `69d80d5` حتى `4e469fd`)، وبعضها لا يزال محليًا غير مؤكَّد (uncommitted) بانتظار هذا الاختبار قبل أي commit جديد. **الحاويات المحلية (Docker) أُعيد بناؤها للتو وتشمل كل التغييرات أدناه** — لا حاجة لإعادة بناء إلا إذا طلب المستخدم ذلك صراحة.

## قبل البدء

- الرابط: **http://localhost:3001**
- حساب SUPER_ADMIN: البريد `superadmin@tba.sa`، وكلمة المرور من متغير `ADMIN_DEFAULT_PASSWORD` في ملف `.env.local` بجذر المشروع (اطلبها من المستخدم إن لم تستطع قراءة الملف).
- **لا يوجد مستخدمو اختبار جاهزون لأدوار MEDICAL_REVIEWER وPROVIDER_STAFF.** أنشئهما بنفسك عبر `/admin/users` (كـ SUPER_ADMIN أولاً) قبل اختبار تلك الأقسام. لـ PROVIDER_STAFF، تحتاج ربطه بمزوّد خدمة (provider) موجود فعليًا — أنشئ واحدًا بسيطًا إن لم يوجد.
- افتح أدوات المطوّر (DevTools) في المتصفح وراقب تبويب **Console** (أخطاء JS) وتبويب **Network** (أكواد الحالة 403/404/500) طوال الاختبار.

## القسم 2 — الموافقات المسبقة (Pre-Authorization Review Workflow)

كـ SUPER_ADMIN أو MEDICAL_REVIEWER:
- [ ] عنصر قائمة **"مراجعة الموافقات المسبقة"** ظاهر في مجموعة "المطالبات والموافقات" (بجانب "طلبات البريد (Pre-Auth)" القديم — يجب أن يظهر الاثنان معًا، وليس واحدًا فقط).
- [ ] `/pre-approvals/review` يفتح صندوق وارد الموافقات المسبقة (ليس فارغًا/معطوبًا).
- [ ] `/pre-approvals/email-inbox` لا يزال يعمل كصفحة قديمة (legacy) منفصلة.
- [ ] فتح طلب موافقة مسبقة وتجربة زر **"طلب استكمال بيانات"** — يفتح حوارًا ويرسل الطلب دون خطأ.
- [ ] كـ PROVIDER_STAFF: `/provider/pre-auth-inbox` يعرض **كل الحالات** (ليس فقط المعتمدة) — جرّب فتحه وتأكد من ظهور طلبات بحالات متعددة إن وُجدت بيانات.

## القسم 3 — مراجعة التصنيف وقوائم الأسعار (Classification / Price Lists)

كـ SUPER_ADMIN:
- [ ] `/classification/review` يُفتح دون صفحة فارغة.
- [ ] تبويبات الفلترة: **موثوقة، معتمدة، غير مصنفة، ومكرَّرة (تبويب جديد)** — كلها تعمل دون صفحة فارغة أو خطأ.
- [ ] اعتماد سطر من تبويب "غير مصنفة" ينقلك تلقائيًا لتبويب "معتمدة" بعد الحفظ.
- [ ] السطور المعتمدة/المرفوضة لا يظهر لها زر "اعتماد" مرة أخرى.
- [ ] الضغط المتكرر السريع على "اعتماد" لا يرسل الطلب مرتين (لا تكرار في النتيجة).
- [ ] افتح قائمة أسعار عقد مزوّد (Provider Contract → قائمة الأسعار)، جرّب **"إضافة خدمة جديدة"**: املأ (تصنيف + سعر + سبب) وأرسل. تحقق من تبويب Network أن الطلب المُرسَل يحتوي **`categoryId`/`price`/`reason`** حصرًا (وليس `medicalCategoryId`/`basePrice`/`contractPrice`/`notes`)، وأن العملية تنجح ويظهر العنصر الجديد بعد إعادة تحميل الصفحة.
- [ ] زر "إضافة خدمة جديدة" مفعّل طالما يوجد عقد، حتى لو لم توجد نسخة أسعار نشطة بعد.

## القسم 4 — أدوات الصيانة (Maintenance Tools)

كـ SUPER_ADMIN — هذا القسم يحتوي **إصلاحًا حرجًا للتو**، اختبره بعناية:

- [ ] من "فئات النظام"، افتح كل أداة صيانة **واحدة تلو الأخرى دون إغلاق نافذة الإعدادات بينهما** (هذا كان يسبب عطلاً سابقًا — بقاء التبويب القديم بدل التبديل):
  - [ ] **تصحيح بيانات المستفيدين** (`/settings/kinship-mismatch`) — يفتح ويعرض بيانات (أو رسالة "لا توجد بيانات"، وليس صفحة بيضاء/خطأ).
  - [ ] **دمج السجلات المتكررة** (فتحه عبر تبويب "فئات النظام") — **كان به خطأ مؤكَّد** (رابط API مكرر البادئة يسبب 404) **وتم إصلاحه للتو** — تحقق أنه يعرض قائمة السجلات المتكررة الآن دون خطأ في Console/Network، وأن دمج مجموعة يعمل.
  - [ ] **النسخ الاحتياطي والاستعادة** — يفتح على التبويب الصحيح مباشرة (وليس التبويب الافتراضي "معلومات المؤسسة").
  - [ ] **التنبيهات والمراقبة** — نفس الشيء، يفتح على التبويب الصحيح.
  - [ ] **سجل أخطاء النظام** — نفس الشيء.
- [ ] تحقق أن أدوات الصيانة **لا تظهر إطلاقًا** لأي دور غير SUPER_ADMIN (جرّب مع MEDICAL_REVIEWER — لا يجب أن ترى "فئات النظام" تحتوي مجموعة "أدوات الصيانة" أصلاً).

## القسم 8 — صفحة الإعدادات (Settings) — إعادة تنظيم مع قرار منتج جديد

كـ SUPER_ADMIN، افتح `/settings/system` وتحقق من التبويبات بالترتيب:

- [ ] **معلومات المؤسسة** — موجود ويعمل.
- [ ] **قواعد الاستحقاق** — موجود ويعمل.
- [ ] **المحرك التشغيلي** (تبويب جديد أُضيف للتو) — يفتح ويعرض: SLA المطالبات (يوم)، SLA الموافقات (يوم)، السماح بمطالبات قديمة (أشهر)، تنسيق رقم المستفيد، **البادئة** (حقل نصي، القيمة الافتراضية حاليًا `TD`)، عدد الأرقام. جرّب تعديل حقل "البادئة" والحفظ، وتأكد أن القيمة تُحفظ بعد إعادة تحميل الصفحة.
- [ ] **إعدادات التقارير** — موجود ويعمل.
- [ ] **بوابة مقدم الخدمة** — موجود ويعمل (تفعيل/تعطيل البوابة).
- [ ] **المظهر** — موجود ويعمل.
- [ ] **تأكد أن التبويبات التالية لم تعد موجودة إطلاقًا** (أُلغيت بقرار صريح): "إعدادات البريد"، "إعدادات الذكاء الاصطناعي"، "قواعد التغطية المالية" (محرك القواعد المالية). يجب ألا تظهر لا كتبويب مرئي ولا عبر أي رابط مباشر.
- [ ] جرّب فتح الرابط `/settings/ai-key` يدويًا في شريط العنوان — يجب أن يُعطي صفحة غير موجودة (404) أو إعادة توجيه، **وليس** صفحة إعدادات الذكاء الاصطناعي (كانت موجودة كرابط منسي، وحُذفت).
- [ ] لا أخطاء Console عند التنقل بين كل التبويبات المذكورة أعلاه.

## التقرير المطلوب

أرسل تقريرًا مفصّلاً يتضمن **لكل قسم أعلاه**:
1. نجح / فشل (لكل بند على حدة، ليس فقط لكل قسم).
2. أي رسالة خطأ ظهرت في Console حرفيًا.
3. أي طلب Network فشل (الكود + الرابط الكامل).
4. لقطات شاشة أو وصف دقيق لأي سلوك غير متوقع.
5. توصية نهائية لكل قسم: **يعمل بشكل صحيح** أو **يحتاج إصلاحًا — وصف المشكلة بدقة**.
6. توصية إجمالية: **جاهز للـ commit والدفع** أو **يوجد مشاكل يجب إصلاحها أولاً (قائمة بها)**.

لا تُجرِ أي تعديل على الكود، ولا commit، ولا push، ولا merge. هذه مهمة اختبار فقط.
