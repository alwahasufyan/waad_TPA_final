# مهام اختبار المتصفح (Browser Smoke Test) — لتنفيذها بواسطة Claude الذي يملك وصول متصفح

انسخ هذا الملف بالكامل والصقه في محادثة مع Claude الذي يملك أداة تحكم بالمتصفح (مثل Claude for Chrome / Computer Use). هذه المهمة **اختبار فقط** — لا تعديل كود، لا commit، لا push.

## السياق

مشروع WAAD TPA، الفرع `medical-dictionary-remediation` (آخر commit: `4e469fd`) جاهز للدمج في `main`، لكن يحتاج اختباراً بشرياً/متصفحياً حقيقياً قبل ذلك. الجلسة السابقة (بدون متصفح) تحققت فقط من أن الباك-إند يُبنى (`mvn compile`) والفرونت-إند يُبنى (`vite build`) بنجاح — لم يُفتح أي متصفح بعد.

## قبل البدء — تحقق أولي (مهم)

يوجد Stack دوكر يعمل بالفعل محليًا (containers باسم `waad-local-backend` على المنفذ 8081، و`waad-local-frontend` على المنفذ 3001)، لكنه **مبني من قبل آخر 3 commits** في هذا الفرع (أي قد لا يعكس آخر إصلاحات classification). قبل الاختبار:

1. اسأل المستخدم (الشخص الذي أعطاك هذه المهمة): "هل الـ containers الحالية على المنفذ 3001/8081 محدّثة لآخر commit `4e469fd`، أم يجب إعادة بنائها؟"
2. إذا لزم إعادة البناء، شغّل من جذر المشروع (PowerShell):
   ```
   ./waad.ps1 rebuild
   ./waad.ps1 up
   ./waad.ps1 health
   ```
   لا تشغّل `rebuild`/`up` بدون تأكيد من المستخدم إن كانت الحاويات الحالية تعمل منذ فترة طويلة — قد تكون بيئة عمل يعتمد عليها المستخدم لأغراض أخرى.

## بيانات الدخول

- الرابط: **http://localhost:3001**
- حساب SUPER_ADMIN الافتراضي:
  - البريد: `superadmin@tba.sa`
  - كلمة المرور: القيمة الموجودة في متغير `ADMIN_DEFAULT_PASSWORD` داخل ملف `.env.local` بجذر المشروع (لا تخمّنها ولا تفترضها — اطلب من المستخدم القيمة إذا لم تستطع قراءة الملف).
- **لا يوجد مستخدمو اختبار جاهزون لأدوار MEDICAL_REVIEWER و PROVIDER_STAFF.** يجب إنشاؤهما بنفسك عبر واجهة إدارة المستخدمين (كـ SUPER_ADMIN أولاً) قبل اختبار تلك الأدوار:
  - أنشئ مستخدمًا بدور `MEDICAL_REVIEWER` (بريد اختباري، كلمة مرور من اختيارك، دوّنها).
  - أنشئ مستخدمًا بدور `PROVIDER_STAFF` **مرتبطًا بمزوّد خدمة (provider) موجود فعليًا** في النظام — إن لم يوجد مزوّد اختباري، أنشئ واحدًا بسيطًا أولاً كـ SUPER_ADMIN، ثم اربط المستخدم به.
  - إن واجهت صعوبة في الإنشاء، أبلغ في التقرير النهائي بدل الاستمرار بتخمين بيانات.

## خطوات الاختبار

### 1) تسجيل الدخول كـ SUPER_ADMIN
افتح http://localhost:3001 وسجّل الدخول. تحقق:
- [ ] تسجيل الدخول ينجح بدون خطأ
- [ ] لوحة التحكم (Dashboard) تُفتح فعليًا
- [ ] لا أخطاء واضحة في console المتصفح (افتح DevTools → Console، خذ لقطة/انسخ أي رسالة حمراء)

ثم افتح كل رابط من التالي وتحقق أنه يُفتح بدون صفحة بيضاء/خطأ 403/500:
- [ ] System Categories (من القائمة الجانبية أو `/dashboard` → أيقونة الفئات)
- [ ] `/claims/review`
- [ ] `/pre-approvals/review`
- [ ] `/pre-approvals/email-inbox` (يجب أن يبقى يعمل كصفحة "قديمة/legacy")
- [ ] `/provider-contracts`
- [ ] `/classification/review`
- [ ] `/settings/system`
- [ ] تحقق أن أدوات الصيانة (Maintenance tools) تظهر **مرة واحدة فقط**، وليست مكررة في القائمة

### 2) تسجيل خروج، ثم دخول كـ MEDICAL_REVIEWER
- [ ] `/claims/review` يُفتح
- [ ] `/pre-approvals/review` يُفتح
- [ ] `/admin/users` يُرفض بـ 403 (أو يُعاد التوجيه لصفحة "غير مصرح")
- [ ] `/settings/system` يُرفض بـ 403
- [ ] `/provider-contracts` يُرفض بـ 403 (إلا إذا وجدت أن هذا الدور مسموح له عمدًا — إذا كان مسموحًا، دوّن ذلك بدل اعتباره خطأ)

### 3) تسجيل خروج، ثم دخول كـ PROVIDER_STAFF
- [ ] بوابة المزوّد (Provider Portal) تُفتح
- [ ] `/provider/pre-auth-inbox` يُفتح
- [ ] `/provider/eligibility-check` يُفتح
- [ ] `/pre-approvals/review` يُرفض بـ 403
- [ ] `/claims/review` يُرفض بـ 403
- [ ] `/admin/users` يُرفض بـ 403

### 4) اختبار مسار التصنيف (Classification) — إن وُجدت بيانات
- [ ] صفحة `/classification/review` تُحمَّل بدون صفحة فارغة
- [ ] تبديل الفلاتر (تبويبات: موثوقة/معتمدة/غير مصنفة/مكررة) لا يُنتج صفحة فارغة أو خطأ
- [ ] افتح حوار "إضافة خدمة جديدة" (Add Service) من قائمة أسعار عقد مزوّد (Provider Contract price list)، واملأه ببيانات صحيحة (تصنيف + سعر + سبب)، وأرسل — تحقق أنه **لا يُرسل حقولاً خاطئة** (تحقق من تبويب Network في DevTools: يجب أن يرسل `categoryId`/`price`/`reason`، وليس `medicalCategoryId`/`basePrice`/`contractPrice`/`notes`)، وأن العملية تنجح ويظهر العنصر الجديد بعد إعادة تحميل الصفحة

## التقرير المطلوب

بعد الانتهاء، أرسل تقريرًا يتضمن بالضبط:
1. هل الـ containers كانت محدّثة لـ `4e469fd` أم أُعيد بناؤها، وكيف تحققت من ذلك
2. نتيجة تسجيل الدخول لكل دور (نجح/فشل)
3. قائمة الصفحات المختبرة ونتيجة كل واحدة (تعمل / معطوبة / محظورة بشكل صحيح / محظورة بشكل خاطئ)
4. أي أخطاء console ظهرت (نص الخطأ كاملاً)
5. نتيجة اختبار "إضافة خدمة" في التصنيف (نجح/فشل + ما أُرسل فعليًا للباك-إند)
6. توصية نهائية: **READY_TO_MERGE** أو **DO_NOT_MERGE — السبب**

لا تُجرِ أي تعديل على الكود، ولا commit، ولا push، ولا merge. هذه مهمة اختبار فقط.
